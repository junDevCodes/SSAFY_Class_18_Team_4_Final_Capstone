## 1. 프로젝트 개요

### 1.1 프로젝트 목적
신선한 농산물을 소비자와 생산자(판매자)를 직접 연결하여, 소비자가 원하는 상품을 추천해주고, 가장 저렴하게 찾을 수 있는 전자상거래 플랫폼 구축

### 1.2 프로젝트 범위
| 구분 | 내용 |
|------|------|
| **In Scope** | 회원 관리, 상품 관리, 주문/결제, 판매자 시스템, 브랜드몰, **리뷰/평점 시스템**, **추천 알고리즘** |
| **Out of Scope** | 실제 PG 결제 승인 연동 (모의 결제로 대체), 실시간 배송 추적 API 연동 |

### 1.3 팀 구성
| 이름 | 역할 | GitHub | 담당 기능 |
|------|------|--------|-----------|
| 이준영 | 팀장/Data/AI/Embeded/DevOps | [@junDevCodes](https://github.com/junDevCodes) | Data 분석 & 인사이트 도출, CI/CD 파이프라인 구축 |
| 배용건 | Frontend | [@dragun8](https://github.com/dragun8) | MVP 설계, UI/UX 구현 |
| 송준서 | Backend/DevOps/AI Agent | [@Junseo5](https://github.com/Junseo5) | API 개발, DB 설계, 기능 개발 |

### 1.4 개발 일정
| 단계 | 기간 | 산출물 |
|------|------|--------|
| 기획 및 설계 | 11.10 ~ 11.21 | ERD, API 설계서, 화면 설계서 |


## 5. 기능 요구사항

### 5.1 인증 시스템 (AUTH)

#### AUTH-001: 이메일 회원가입
| 항목 | 내용 |
|------|------|
| **요구사항 ID** | AUTH-001 |
| **요구사항명** | 이메일 회원가입 |
| **우선순위** | 필수 (P1) |
| **설명** | 사용자가 이메일과 비밀번호로 회원가입을 할 수 있다 |
| **선행조건** | 없음 |
| **후행조건** | 이메일 인증 필요 |
| **입력** | 이메일, 비밀번호, 비밀번호 확인, 사용자명 |
| **출력** | 인증 코드 이메일 발송, 회원가입 대기 상태 생성 |
| **비즈니스 규칙** | - 이메일 형식 검증<br>- 비밀번호 최소 8자 이상<br>- 이메일 중복 확인<br>- 인증 코드 24시간 유효 |
| **예외 처리** | - 이메일 중복 시 오류 메시지<br>- 비밀번호 불일치 시 오류 메시지 |

#### AUTH-002: 이메일 인증
| 항목 | 내용 |
|------|------|
| **요구사항 ID** | AUTH-002 |
| **요구사항명** | 이메일 인증 |
| **우선순위** | 필수 (P1) |
| **설명** | 발송된 인증 코드로 이메일 소유권을 확인한다 |
| **선행조건** | AUTH-001 완료 |
| **후행조건** | 회원 계정 활성화 |
| **입력** | 이메일, 인증 코드 |
| **출력** | 인증 완료 메시지 |
| **비즈니스 규칙** | - 인증 코드 일치 확인<br>- 만료 시간 확인 (24시간)<br>- 인증 완료 시 User 생성 |
| **예외 처리** | - 코드 불일치 시 오류<br>- 만료된 코드 시 재발송 안내 |

#### AUTH-003: 로그인
| 항목 | 내용 |
|------|------|
| **요구사항 ID** | AUTH-003 |
| **요구사항명** | 이메일/비밀번호 로그인 |
| **우선순위** | 필수 (P1) |
| **설명** | 이메일과 비밀번호로 로그인한다 |
| **선행조건** | AUTH-002 완료 (이메일 인증됨) |
| **후행조건** | JWT 토큰 발급 |
| **입력** | 이메일, 비밀번호 |
| **출력** | Access Token, Refresh Token, 사용자 정보 |
| **비즈니스 규칙** | - 이메일 인증 완료 확인<br>- Access Token 15분 유효<br>- Refresh Token 7일 유효 |
| **예외 처리** | - 이메일/비밀번호 불일치<br>- 미인증 계정 |

### 7.2 도메인별 주요 테이블

#### Group 1: Users & Auth
| 테이블 | 설명 |
|--------|------|
| users | 회원 계정 기본 정보 (이메일, 사용자명, 역할, 활성화 상태) |
| user_profiles | 프로필 확장 정보 (연락처, 생년월일, 성별, 알림/마케팅 설정) |
| user_addresses | 배송지 주소록 (수령인 정보, 기본 배송지 여부) |
| pending_registrations | 이메일 회원가입 인증 대기 |
| auth_email_credentials | 이메일/비밀번호 로그인 자격 정보 |
| auth_google_accounts | Google OAuth 연결 정보 |
| auth_kakao_accounts | Kakao OAuth 연결 정보 |

#### Group 2: Seller Domain
| 테이블 | 설명 |
|--------|------|
| sellers | 판매자 브랜드 정보 (브랜드명, 슬러그, 로고, 상태) |
| seller_businesses | 사업자 등록/인증 정보 (사업자번호, 유형, 증빙 서류) |
| seller_settlements | 정산 계좌 정보 (은행, 계좌번호, 예금주) |
| seller_schedules | 요일별 영업 시간/휴무일 |

#### Group 3: Product Domain
| 테이블 | 설명 |
|--------|------|
| categories | 계층형 상품 카테고리 |
| products | 상품 기본 정보 (상품명, 가격, 상태, 배송 정보) |
| product_details | 상품 상세 설명, SEO 메타 정보 |
| product_inventories | 재고 수량, 안전 재고 수준 |
| product_images | 상품 이미지 목록 (표시 순서 포함) |

#### Group 4: Orders & Payments
| 테이블 | 설명 |
|--------|------|
| orders | 주문 헤더 (주문번호, 상태, 취소/환불 정보) |
| order_items | 주문 품목 (상품 스냅샷, 수량, 품목별 상태) |
| shipments | 배송 정보 (수령인, 주소, 택배사, 운송장) |
| payments | 결제 트랜잭션 (결제 수단, 금액, 상태, PG 정보) |

#### Group 5: Interactions
| 테이블 | 설명 |
|--------|------|
| carts | 장바구니 (사용자-상품 유니크) |
| wishlists | 찜 목록 (사용자-상품 유니크) |
| seller_follows | 판매자 팔로우 관계 |

#### Group 6: Reviews
| 테이블 | 설명 |
|--------|------|
| reviews | 상품 리뷰 (평점, 내용, 구매 연결, 상태) |
| review_images | 리뷰 이미지 목록 |

#### Group 7: Recommendation & Analytics
| 테이블 | 설명 |
|--------|------|
| product_stats | 상품별 집계 (조회수, 주문수, 평점, 품질 점수 등) |
| user_product_stats | 사용자×상품별 개인화 집계 (조회/담기/구매 횟수) |

> **상세 ERD**: `erd/DATABASE_SCHEMA_DETAILED.md` 문서 참조

## 10. 용어 정의

| 용어 | 정의 |
|------|------|
| JWT | JSON Web Token. 사용자 인증에 사용되는 토큰 |
| Access Token | 짧은 유효기간(15분)의 인증 토큰 |
| Refresh Token | 긴 유효기간(7일)의 토큰 갱신용 토큰 |
| OAuth2 | 소셜 로그인을 위한 표준 인증 프로토콜 |
| PK | Primary Key. 테이블의 기본 키 |
| FK | Foreign Key. 외래 키 |
| slug | URL에 사용되는 고유 식별자 (예: fresh-apple) |
| CRUD | Create, Read, Update, Delete. 기본 데이터 조작 |
| SPA | Single Page Application. 단일 페이지 애플리케이션 |
| REST API | Representational State Transfer API |
| Soft Delete | 데이터를 물리적으로 삭제하지 않고 삭제 플래그로 표시 |
| 스냅샷 | 특정 시점의 데이터 복사본 (주문 시 상품 정보) |
| MVP | Minimum Viable Product. 최소 기능 제품 |
| 모의 결제 | 실제 PG 연동 없이 결제 플로우를 시뮬레이션하는 방식 |
| 협업 필터링 | 유사한 사용자의 행동 패턴을 기반으로 추천하는 알고리즘 |
| 품질 점수 | 상품의 이미지/콘텐츠/리뷰 등을 종합한 품질 지표 |
| 감성 점수 | 리뷰 텍스트의 긍정/부정 정도를 수치화한 지표 |
